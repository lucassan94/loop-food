## ⚠️ Achados de ambiente (afetam a execução)

1. **Rate limit de login (5 tentativas / 15 min / IP)** em **todos** os endpoints `/auth/*/login` (um único `loginLimiter`). Qualquer automação precisa respeitar a janela. **Evidência adicional:** o tráfego via nginx (domínio HTTPS) parece consumir um **bucket diferente** do acesso direto à API por IP (probes simultâneos retornaram `RateLimit-Remaining: 0` no direto com 401 e 429 no HTTPS) — suspeita de `req.ip` = IP do nginx para tráfego UI (bucket GLOBAL compartilhado entre todos os clientes). **A investigar** (ver 02. bugs-aware.md BUG-014).
2. **Usuários seed `cliente` e `entregador` NÃO existem no tenant deployado** (401 — o banco foi limpo sem re-aplicar o seed). Os testes usam usuários de teste persistentes: cliente `(11) 97000-7777` / `cliente123` (criado via signup) e entregador id 7 `(11) 97000-8888` / `entregador123` (resetado via admin). Ver 01. pendings.md.
3. **Fix do CEP não deployado:** `cep.js` local já lança `AppError` (400/404 com código), mas o deploy retorna **500** para CEP inexistente → API-05 falha (única falha real da API).
4. **Feature Salão desativada no deploy** (`features: {salao: false, delivery: true}`) → KDS/PDV/Mesas não aparecem no painel (RS-17/18 não aplicáveis).
5. **App do entregador não lista pedidos cancelados** — `loadData` só busca `pronto_entrega`, `em_transito/cheguei_destino` e `entregue`. O motivo do cancelamento é salvo no backend mas nunca exibido na UI (EN-15 = verificado via API; gap documentado em 02. bugs-aware.md BUG-013).

## 🔧 Notas de implementação das suítes

- **Rate limit de login:** as suítes aguardam a janela (15 min) antes de rodar e usam o header `RateLimit-Remaining` para garantir folga. Suítes devem rodar **uma por janela** (CL = 2 logins, RS = 1, EN = 3).
- **Usuários persistentes de teste:** `tmp_ui_tests/.cliente-teste.json` (cliente) e `.entregador-teste.json` (entregador) — criados por `setup-entregador.js` e pelo signup (cliente). O `client.js` NÃO sobrescreve o telefone do perfil no reset de endereço (correção para não invalidar o login da próxima execução).
- **Viewport:** painel do restaurante é desktop-first → `1280×800` (a 420px o CSS esconde os labels da sidebar); cliente/entregador usam `420×900` (mobile).
- **Dados de teste gerados:** pedidos (`Teste RS Aceitar`, `Cliente EN *`), categorias `Cat UI *` (não removidas pelas suítes), usuário de teste (cliente id 42, entregador id 7), raios (removidos). Rodar `limpar-dados-teste.js` / limpeza manual antes de um go-live.
